## [0.2.3] - 2026-11-09

### Added
- `doctor` command: read-only inbox health self-check (`Inbox.doctor()` returns a report with an ok flag, a list of issues, and md5 fingerprints). It checks that every known file is present and reachable (not a symlink, inside the root), that every non-empty file ends with a newline, that every entry-looking line matches the entry format and no entry ID is used twice, that every index row matches the row format with a known category and a valid timestamp, that the index and the category files hold the same set of IDs, and that no file is world-writable. A missing file reports just itself, not a cascade of consistency errors, and a doctor run never writes — an uninitialized inbox is reported and left untouched. The CLI prints one `[ok]` / `[error]` / `[warning]` line per check plus the fingerprints, ends with `OK: inbox is healthy` or `doctor found N error(s) and M warning(s)`, and exits 1 when any error is found.

## [0.2.2] - 2026-11-07

### Added
- `import` command: import entries from an exported Markdown or JSON file (`--file`, `--format auto|json|markdown` auto-detected from the suffix, `--dry-run` preview). Markdown accepts both the `export` output (`- [ID] timestamp [category] text`) and raw category-file lines (`- [ID] timestamp — text`, with `--category` naming the category). Timestamps are preserved, entry IDs are freshly assigned for the target inbox, and entries already present (same category, timestamp, and text) are counted as duplicates and skipped — both against the inbox and within the file. The whole file is validated before anything is written, so a bad file imports nothing; `--dry-run` writes nothing at all. Library method `Inbox.import_entries()` returns the imported entries, the duplicate count, and the dry-run flag.

## [0.2.1] - 2026-11-06

### Added
- Search filters: `search --since YYYY-MM-DD` keeps only entries dated on or after that day (boundary day included), `search --category` restricts the search to one category file; both compose with `--tag`. A filtered search matches entry lines only, so hand-written headers and notes never match. `Inbox.search()` gains matching `category` / `since` parameters; unknown categories and invalid dates raise `ValueError`.
- Worked example inbox: `examples/sample-inbox/` — 12 fully fictional entries across five days, covering all four categories and English plus Chinese `#tags`, generated by the new deterministic `examples/generate-sample-inbox.py` (re-running it produces byte-identical files).
- `docs/walkthrough.md`: a step-by-step walkthrough that queries the sample inbox (verify, stats, tag-filtered search, list filters, JSON/Markdown export) with exact expected output, then files entries into a fresh inbox; points onward to `docs/protocol.md` and `SKILL.md`.
- Test coverage for the worked example: `verify` on the shipped sample, byte-for-byte reproducibility of the generator, feature coverage (all categories, tag filters, chronological order), and walkthrough completeness.

## [0.2.0] - 2026-11-03

### Added
- GitHub issue templates (bug report, feature request) and a pull request template with a checklist (tests, CHANGELOG, docs, desensitization scan).
- Chinese template pack `templates/zh/`: Chinese editions of the four category templates, the index, and a `README.md` usage guide (same filenames, Chinese headers and guidance comments; drop-in over `templates/`).
- `docs/protocol.md`: the full protocol reference — trigger words, clock discipline, classification, the seven filing steps, entry/index line formats, tag syntax, query protocol, hard rules, and the security model. `SKILL.md` remains the short operational edition.
- Tag support: entry text may carry `#tags` (Unicode-aware, case-insensitive, deduplicated); `Inbox.list_entries(..., tag=...)` and `Inbox.search(query, tag=...)` filter by tag, `Entry.tags` exposes the parsed tags, and the CLI gains `search --tag` and `list --tag` (a leading '#' in the filter is accepted).
- `list` command: list entries, optionally filtered by `--category` and/or `--date` (YYYY-MM-DD), in chronological order; non-entry lines are skipped.
- `stats` command: total entries, per-category counts (all four categories, zero when empty), earliest/latest entries in chronological order, and total entry-text characters; empty inboxes report `earliest: none` / `latest: none`.
- `export` command: export the whole inbox as one Markdown document (default) or one JSON array (`--format json`), with the same `--category` / `--date` filters, to stdout or to `--output` file (parent directories are created); empty inboxes export as a Markdown header with `no entries` or as `[]`, with matching library method `Inbox.export()`.

### Security
- `--root` hardening: a symlinked inbox root (or a symlink anywhere in its existing parent prefix) is rejected; relative roots containing `..` that would climb above the working directory are rejected. Every file the inbox reads or writes must be one of the five whitelisted filenames (four category files + index), must resolve inside the resolved inbox root, and must not be a symlink — `add` / `verify` / `search` now raise instead of following a swapped-in link.
